## 现在能做什么

- 在 **设置 → 插件配置 → 日志查询** 卡片里增删改「日志来源」（类型 / 名称 / 地址 / ES 的**索引表达式**）与插件开关。
- 让 agent 用这几个工具查（配好来源之后，**名单以 [src/tools.ts](./src/tools.ts) 的注册处为准**）：
  `loglens_sources` 列来源（含**解析后的索引表达式**与探测条数）、
  `loglens_search` 查（支持 `filters` 结构化过滤与 `level` 及以上筛选）、`loglens_fields` 看有哪些字段
  （ES / OpenSearch 侧：**不列 `object` / `nested` 容器行**，同名在不同索引里**类型不一致**的标
  `conflict: true` 并带 `esTypes` / `conflictDescriptions`）、
  `loglens_facets` 按字段分组 / 按时间分桶（「哪个服务在报错」）、`loglens_context` 取某一行前后的上下文。
  可查后端：**Loki**、**Elasticsearch**、**OpenSearch**（Docker 走现成的 `docker_logs` / `docker_logs_grep`）。
  它们**全部**归 **read** 档（分类表见 [docs/permission-tier-plan.md](../../docs/permission-tier-plan.md) §2.1）。
- **在同一张卡片里直接查**：来源 / 查询串 / 时间窗（15m · 1h · 6h · 24h，外加点柱放大时的
  「自定义」那一档）/ 条数 → 结果列表（时间到毫秒 · 级别 · 正文，**正文里命中的那几段会高亮**）
  + 诚实的计数与截断提示（**「确定还有」与「可能还有」分开说**——命中数恰好等于条数上限时
  不说成「已截断」，也不给一个翻过去必然空页的「下一页」；判据在 [src/query.ts](./src/query.ts)
  的 `pageLimitFlags`，有精确总数才判得准，Loki 没有总数就只说「可能」）；
  有游标时给「下一页」（按 id 去重）。查询串那格的**占位提示按来源方言走**：Loki 是 LogQL、
  ES / OpenSearch 是 Lucene（`query_string`），不再对 ES 说「Loki 是 LogQL」。
  查询串那一行下面有一排**可点的例子**（按来源方言给：ES 是 `error` / `"Failed to"` /
  `error AND failed` / `stream:stderr`，Loki 是 `{job="app"} |= "error"` 这类）——点一下填进框里，
  **不自动查**（先看清楚，必要时改一改）。例子本身不翻译（它是代码不是文案）。
  **查询串支持字段名补全**：打字时候选浮层列出这个来源的字段（前缀命中的排前面，最多 20 条），
  点一条就原位补成 `字段:` 并把光标摆到冒号后。补全不自动发起查询；字段清单在第一次需要时
  **自己拉**（按来源缓存 + 在途闩，一个来源一次会话只拉一次），不用先去点别处。
  **正文高亮由后端给位置、界面只负责画**：ES 的 `highlight` 被换算成字符区间（`line.highlights`），
  界面绝不拿查询串去正文里做字面匹配——`stream:stderr` 正文里没有这几个字、`-failed` 是排除、
  `error*` / `~` 各有各的规则，照字面标会错一半，而**标错比不标更坏**。拿不到位置就整段纯文本。
  注意 **Kibana 的 Discover 默认是 KQL，不是 Lucene**（占位符写着 KQL 就是那一套）：
  「且」在 KQL 是 `and`，在 Lucene 是**大写** `AND`（小写会被当成普通词）；写错了不报错，
  只是数字不对。本面板是 Lucene。
  ES / OpenSearch 的查询串**原样**交给 `query_string`，面板不改写：留空即全量（`match_all`）；
  `"短语"`、`a OR b`（**空格分隔的词默认是「或」**，要「与」得写**大写** `AND`——小写 `and`
  会被当成普通词，`a+b` 里的 `+` 也只是分隔符、与空格同义，都不是「且」）、
  `name*` 都按 Lucene 的规则走。`level:ERROR` 常回 0 条不是坏了——这套索引里 `log.level`
  多半为空、级别是从正文**推断**的（行上有 `levelInferred`），按级别筛请用级别下拉。
  **查询串写错时能看到原因**：ES 对分片级错误回 `HTTP 200`，原话在 `_shards.failures[].reason`
  里——现在它会被带成一行 `[分片] <ES 原话>` 摆在结果上方（`q=level:(ERROR` 会显示
  `[分片] Failed to parse query [level:(ERROR]`）。在此之前这里只写「已截断：部分分片失败」，
  与真的分片故障长得一样，而「少打一个括号」和「集群出问题」该找的人不同。
- **条件改了、结果还没重查时，界面会说出来**：查询串 / 时间窗 / 级别 / 条数 / 筛选 / 来源任一处改动后，
  结果区顶上一句「下面这份还是上一次查询的」，同时收起「下一页」并禁用「分组」。这不是观感问题——
  **ES / OpenSearch 的翻页游标是 PIT + `search_after`**，拿旧游标配新条件翻页**不会报错**，只会静默
  少行 / 错位；「分组」也会把新查询串配上一次回显的窗口。先点「查询」把两边对齐，入口才回来。
- **两种聚合都在卡片里画**（都由宿主随 `/query` 响应下发的能力自述决定画不画，面板不按类型猜）：
  **时间分布**（按时间分桶的柱状图）与**按字段分组**（terms 榜——「哪个服务在报错」的那个答案）。
  时间分布上**有数据的柱子点一下就是放大到那一段**：时间窗夹到那一档再重查一次（行、分布、榜一起收窄），
  正在放大的那一档高亮着，下拉变成按**真实范围**现算的「自定义」；再换回预设档就把这一段撤掉。
  **空桶不给点**（点进一个 0 条的窗口只会得到「没有命中」，看不出是自己点的），
  **被下限（1 分钟）夹过会明说**一句（静默收窄比报错更难查）。
  榜要先填一个分组字段：手填，或**点开那一格**看当前来源的字段名候选（点开即拉，**不传 `limit` = 不截断**，
  摆出来的就是这个来源的全部字段，与 Kibana 的 `_field_caps` 同口径；同一个来源不重复拉，浮层页脚报
  「共 N 个字段」并有「刷新」——长度交给浮层自己的子串过滤 + 滚动去消化）。
  候选是**卡片自己画的浮层**（按宿主菜单的配方取值：圆角、发丝描边投影、行高、hover 底），
  不是浏览器那个原生 `datalist`——输入框里的字按子串过滤候选，方向键挪当前行、回车取它、Esc 收起、点一行即填；
  两个箭头（卡头折叠 / 字段框）都是**官方那颗描边 chevron**。候选里只有「能用的名字」：`object` / `nested`
  这类没有自己值的容器行不列；同名在不同索引里**类型不一致**的字段在行尾标「类型冲突」（悬停列出两种类型）——
  拿它分组只会覆盖一部分索引，所以不标就等于没说。
- **点榜上的一条就是按它下钻**：加一条结构化筛选（宿主契约里的 `filters`）再查一次，行、时间分布与榜
  **一起收窄到同一个子集**；再点一次取消，筛选也能在那一行芯片上用 `×` 一条条去掉。空值那一桶不给点
  （筛选表达不了「字段缺失」，见下「已知限制」）。
- **结果行的右边就是「谁写的」**：行上只摆**1 个**身份标签（宿主顺序里的第一个，通常是容器名；
  只显示**值**，字段名在行悬停 / ＋N 浮层 / 字段面板里），
  **点它就是「字段 = 值」加一条筛选并立刻重查**（与点榜下钻同一条路）——不用先去填「分组字段」
  再看榜，也不用事先知道字段叫什么。其余标签收在行尾的**「＋N」**里：点开是一个列出**全部**标签的
  浮层，点其中任意一条同样立刻筛（点背景 / × / Esc / 一滚就收起）；悬停仍然给全部标签与原文 `raw`。
  值本身不截断（下发的永远是原值；浮层里显示的是 `display`，超长带 `…`）。
  **为什么只留 1 个**（2026-10-17 第九刀）：真机 100 行里 `host.name` 只有一个值、`log.file.path`
  与容器名一一对应，3 个 chip + 「另有 N 个」把行高撑到 4 行；现在短日志行从 ~74px 降到 42px，
  一屏能扫的行数接近翻倍。
- **字段面板是浮层，不占日志宽度**（P8-乙 / 第十二刀，2026-10-17）：元信息行的「字段」按钮点开一块
  **340px 浮层**（高度跟结果区走，字段列表自己滚），结果表始终是整行宽度——正文一直 577px，
  不因它变窄。点面板外任何地方、或再点一次「字段」收起。
  **面板从触发它的那颗按钮长出来**（第二十刀）：右缘对齐按钮右缘、顶边贴按钮下沿 4px，真机量到两者
  横向差 **0px**。改前它钉在结果区左端，而按钮在整行右侧——横向差 **123px**，按的是右边那颗、
  展开的东西出现在最左边（与第十七刀「读数条钉在左端、柱子在图中间」同一条毛病）。
  遮罩也跟着改成全屏 `fixed`：面板浮到元信息行那一层之后，只铺结果区的遮罩会漏掉上面那几块，
  点面板上方的空白会「没反应」。面板里从当前页的
  `labels` 数出**本页命中**的字段（带出现行数），再按 `/fields` 分成**其余可用字段**与**类型冲突**两个区；
  顶部有过滤框，长字段名在点处折行（不是硬切）。**收起时不会去拉 `/fields`**，展开才拉一次（同来源缓存）。
  **过滤是「多词 AND」**（2026-10-17 第二十一刀）：空格分词、每个词都要命中，所以 `cont name`
  和 `container name` 都筛得到 `container.name`——改前只认一整串子串，打空格会得到 0 个结果
  （那不是「没找到」，是「你打的方式这个框不认」，而它是 92 个字段唯一的导航方式）。
  搜索时右上角报**命中几个**（比「一共多少个」有用），并**自动展开全部分组**。
  **字段按父路径分组**：真机上这台来源 **92 个字段里 58 个是 `container.labels.*`**，一层平铺的列表
  把 `agent.name` 这种短名字和 `container.labels.com_docker_compose_project_environment_file`
  这种长名字混排在一起。现在每组一个可折叠的组头（写父路径 + 计数），**行里只写末段**——
  那 58 个折行文字变成 58 个短词（`architecture` / `build-date` / …），父路径由组头说，
  完整名仍在行悬停的 `title` 里。默认只展开**命中区**（那是这个来源真在用的字段），
  其余与冲突折叠（滚动高度从 ~2878px 降到 **1494px**）。
  **长末段断在「词」上**（2026-10-17 第二十三刀）：`container.labels.*` 的末段本身就是 40 个字符上下
  （`com_docker_compose_project_environment_file`），原来靠 CSS 的 `overflow-wrap:anywhere` 让浏览器
  把一行**填满**再断——真机上 `com_docker_compose_config-hash` 被切成 `com_docker_compose_conf` /
  `ig-hash`，一个词从中间裂开。现在 `_` / `-` / `.` 之后各给一个 `<wbr>` 断点，宽度也从 300 加宽到 340：
  真机 92 个字段里折行的从 **10 个降到 6 个**，而剩下那 6 个都断在分隔符后面（`com_docker_compose_project_` /
  `environment_file`）。面板脚注同理：它原来 464px 塞进 284px 的格子、被省略号切在句子中间，
  现在一行短句（「数字是本页行数；列要有逐行值才能加。」）+ 完整那段进 `title`。
  面板里还有一格**已选列**：列芯片画在结果表上方，而面板浮在它上面——从面板里点「列」时芯片正好被
  挡住，看不见自己刚加的那一列。这一格把同一个列集摆在面板里，加与去在同一处。
  **筛选是一条两格输入框，不再是弹层**（2026-10-17 第三十刀）：
  ```
  筛选  [container.name ▾] = [prometheus ▾] [确定]      ← 芯片排在更前面
  ```
  左格选字段（可打字收窄、可方向键挑），选定就把**右格自动张开**并拉该字段的 top 8 值
  （每行一条**相对长短**的条，具体条数在悬停里——它与页面命中数是两个瞬间量出来的，
  真机上抓到过「值行 15242 / 同屏命中 15199」，并排摆必然被读成算错了），
  右格**也能手打**——长尾值、带空格/引号的值、`*` 通配只有手打表达得了，所以「没选中任何候选」
  是正常状态，回车取的是打的那串字。Backspace 在值格有字时删字、值格空了退回字段格。
  **换字段会清空右格**（值属于字段，不属于这一格：不清的话 `host.name` 打的 `node-1` 会被安到
  `container.name` 上，回车就静默筛错）。一个字段**已经在筛**时打开它的值下拉，仍然列得出别的值
  ——请求会摘掉这个字段自己的那条筛选（否则聚合只在「= 当前值」里算，候选永远只有它自己，
  换值只能先删芯片）；摘掉之后那些数不受本字段约束，下拉顶部有一句说明。
  选中一条就按「字段 = 值」立刻重查（与榜下钻、行上标签同一条 `drillDown`）。
  这一刀撤掉了「＋ 筛选」那颗按钮与它背后的**整块筛选弹层**——它们做的是同一件事，而这条件
  的形状本来就只是「字段 = 值」两个词。弹层里还成立的判据（top 值带计数、点值直接筛、手填长尾值、
  按父路径分组）一样进了这一格；**选列面板**（元信息行那颗「字段」）保留，并因此收成单一面板。
  **选列面板只管选列**（2026-10-17 第二十五/二十六刀）：只列**本页命中**的字段（列的值取自每一行的
  标签，其余字段加出来会全是 `—`）；真机上因此从 92 个字段收到 **35 个**（滚动 1470px → 1278px）。
  **每个字段是一个勾选框**：整行可点（点名字、点数字、点勾选框都算选它），勾选框是真的
  `<input type=checkbox>`、选中色走宿主的中性 brand；4 列满员后未选的行变灰禁用（已选的仍可取消
  ——否则满员之后一个都去不掉）。原来那颗「列」按钮删掉了：「列」是操作名，而这一栏做的事是**选择**。
  **缩进是一条竖线**（2026-10-17 第二十七/二十九刀）：组头的箭头与行里的勾选框同占 16px 的前导槽、
  同用 4px 间距；组内的行相对组头右移 **17px** 并挂一条 `.5px` 竖向导轨，一眼看得出谁属于谁。
  真机上原来箭头在 x=199、勾选框在 x=219（差 20px），名字与组名差 28px，现在两条线都是 0 偏差。
  **列只能加「本页命中」的字段**——其余字段没有逐行值，给一个画出来全是 `—` 的列比不给更坏；
  它们仍可筛（从筛选那条两格输入框）。有额外列时结果表改成按列宽排布：正文有 198px 下限，
  窗口不够就**横向滚动**（不加列时仍是原来的 flex 行）。
  **行内只剩「名字 + 计数」两列**（2026-10-17 第十九 / 二十八刀）：计数**右对齐 + 等宽数字**
  （`tabular-nums`）——改前它在 18~21px 之间跳（`100` / `73` / `72`），一列读下来像锯齿；
  分组标题 `position:sticky` 钉在滚动区顶部（字段多到要滚时还知道在看哪一组），
  过滤框带放大镜与「有内容才出现」的 ×。行高 **26px**（动作桶删掉之后它才真的落地）。
- **看日志默认是「完整」模式**（正文全展开，与早先一样）；元信息行有个「紧凑」开关，切过去每条只留 **3 行**
  （带省略号），给「扫一眼找异常」用。选择记在本机浏览器里（`localStorage`，换设备不跟）。
  点**整行**（或行首箭头）展开详情：完整消息 + 全部标签（行上只摆 1 个）+ 原文；原文超过 2 万字符会截断
  并**报出原长**。**级别按严重度染色**（error/fatal 红、warn 橙、info 正常、debug/trace 灰），
  行间一条发丝分隔线——一眼扫过去先看哪一行，不再满屏都是同一种告警色。
- **结果区高度跟着窗口走**：不再是死数 420px（900px 高的窗口里 100 行只露 7 行），改成
  `min(720px, 72vh)` + 300px 下限——同一窗口里露 **11 行**，窗口越高露得越多。
  （2026-10-17 第十五刀把下限从 240 提到 300、上限从 640 提到 720：那次同时把上面三块压掉了一整屏，
  空出来的高度归结果——它是这个面板的主体。）
- **来源配置收得起来**：插件整页里默认收起成一行摘要（`2 个来源 · 当前 一` + 一颗「编辑来源」），
  设置卡里默认展开（那一页的主任务就是配来源）。真机 816×782：展开 1296px → 收起 **1000px**，
  那两行来源表单（~300px）不再常驻在查日志的屏幕上。收起时**不渲染**那些行（不是 `display:none`）。
- **查询区两行、元信息两层**：查询串独占整行剩余宽度（真机 816px 窗口上 **160px → 473px**——它是这个
  面板里唯一要打长串的地方），时间窗 / 级别 / 条数 / 分组字段集中在第二行（原来分组自成一行、右边
  还留着一列永远空着的「回话」位）。元信息拆成「计数 + 四颗按钮」与「宿主的 warning 长句」两层：
  那条 90 字的级别 warning 不再把按钮推到第三行（同一窗口里元信息行 **102px → 28px**）。
- **元信息行那四颗动作按钮带图标**（2026-10-17 第十八刀）：`☰ 字段` / `☰ 紧凑` / `⇅ 时间` / `🗑 清空结果`。
  原来它们是四块**纯文字**按钮，四段不同长度挤在一行里、分不出「哪些是开关、哪些是一次性动作」，
  而「排序」还要把「排序：」拖在按钮上越换越长。图标**逐字取自宿主自己的前端产物**
  （`IconFlatListOutlineRegular` / `IconWrapLinesOutlineRegular` / `IconChevronsUpDownOutlineRegular` /
  `IconTrashOutlineRegular`），配方也照抄：`viewBox 0 0 16 16`、`fill:none`、`stroke:currentColor`、
  `strokeWidth 1`。排序按钮上现在只写**档位名**（时间 / 级别 / 正文）——「这是排序」由图标说，
  完整那句（含「只排这一页」的边界）仍在 `aria-label` 与 `title` 里。
  真机读数：前三颗等宽 **62px**，「紧凑 ↔ 完整」切换时**宽度不变**。
- **元信息行有个「排序」入口**（三档循环：时间 / 级别 / 正文）。**排序只作用于已返回的这一页**：
  宿主没有服务端排序（要动 `NormalizedQuery`，属 P8-丁），所以入口的悬停说明自己先写着这句；
  默认「时间」就是**宿主原序**（唯一与翻页游标同源的顺序，不许按 ts 重排——同纳秒的多行是切不开的一组）。
  「级别」从重到轻（fatal → error → warn → info → debug → trace，无级别垫底），同档保持宿主原序。
  选择同样记在 `localStorage`（`loglens.sort`），排序**不发请求**。
- **时间分布能读**：柱子是强调色的浅档（原来取 6% 近黑，整张图只剩鬼影）；柱子下面有**时间刻度**
  （首尾各一格 + 中间按窗口等分并吸附到柱网格，最多 4 格；时刻精度按窗口跨度选：≤2 分钟到秒、
  <12 小时时分、更长带日期）。「最高的那根是哪一分钟」不用再数柱子了。
- **时间分布的读数跟着柱子走**（2026-10-17 第十六 / 十七刀）：悬停哪一根，就有一枚气泡**贴在那一根
  的正上方**，写 `19:22 · 315 条 · 占 1%` 并提示「点一下放大到这一段」。位置按柱序号算
  （柱宽是 `flex:1` 等分，序号才是屏幕上的真实位置），真机量到气泡中心与柱子中心**偏差 0px**。
  不悬停时**不画**——钉在左端的那一版被维护者点破（「柱子和信息隔得太远了」）：柱子在图中间、
  读数在最左，每移一格都要横跨大半个屏。气泡也取代了原生 tooltip（那个灰框会盖住横轴刻度，
  里面还写着 `18:28:00.000`）；完整句子搬进 `aria-label` 给读屏用户。
- **峰值那根画得出来**：标题写着「峰值 681 条」，而 681 与常态 460 只差一截——61 根里肉眼挑不出来。
  现在峰值那根柱子用主档强调色（`ll_histBarPeak`），读者一眼能找到它。
- **数据挤成一条平带时改用基线裁剪**：日志量通常很稳（真机那组 61 根里 **50 根落在 60~70%**），
  线性归一化后整张图是一条平带——**图的意义是看差异**，那样等于白画。现在按数据自己挑画法：
  最大 / 最小 ≥ 3 时走线性（诚实、好读），< 3 时从 `min × 0.9` 起画把差异拉开，并**明说**
  「柱高只表示相对高低，不是与条数成正比」；全一样时不裁剪、也不写那句说明。柱高怎么算的判据与
  代价在 [pure.js](./client-src/pure.js) 的 `histogramScale` 头注释里。
- **回车即查**：查询栏里的查询串与条数两个框，按回车就等于点「查询」（只认回车，且按钮灰着时回车
  也发不出去——与按钮同一个条件）。点**正在放大的那根柱**就是取消放大，回到放大之前那一档。
- **级别**在查询栏里有一格下拉（`不限` / `trace+` … `fatal` 七项），走的是宿主**既有**的 `level` 入参。
  选项标签用日志查看器通行的 **`+`** 记号（`warn+` = warn 及以上）而不是「warn 及以上」——那一格最窄
  只有 96px，七项里五项都拖着「及以上」四个字时，一列全是重复的尾巴、级别名反而成了配角。
  **缩短的只是标签**：`+` 的读法与完整口径写在下面那句边界说明里（「级别按『及以上』筛（下拉里的
  warn+ 就是 warn 及以上），且是在『返回的这一页』上筛的」）——语义一个字都没少。
  注意它是**页内筛**：宿主在返回的这一页上过滤，计数与截断提示仍是**未筛的整页**——界面上写着这句。
  要按级别看全量得后端**真有级别字段**：ES 上 `log.level` 常常整列是空的（级别是从正文推断的），
  那种来源连分组榜也拿不到级别，界面把这条前提一起写出来（不再指一条走不通的路）。
- **行上能看出「谁写的」**：filebeat 那类嵌套字段（`container.name` / `host.name` / `log.file.path`）摊成
  点分标签并排在前面；级别归一化成 trace→fatal 六档，文档里没有时从正文推断（此时 `levelInferred: true`，
  `loglens_search` 的 `level` 参数是**及以上**语义）。
- 面板与 agent 工具走**同一个执行层**（[src/execute.ts](./src/execute.ts)）：同一份归一化、同一份截断信号——
  不会出现「面板说的和工具说的不一样」。
- **Docker 目标**在卡片里换成「容器日志」区（**选中这条来源就自动拉容器**，不用点按钮；换 Docker 目标会重拉，
  同一个目标不重复拉，容器会变所以留了一个「刷新」→ 选容器 / 行数 → 看日志），走 Docker 面板插件自己的
  路由（相对路径）；这条路没有 `until`、`tail` 有上限、没有 grep，界面上写着这句，要精确检索请用 agent 侧的
  `docker_logs_grep`。拉容器清单失败时**只落在那一格**（不动卡片顶部那条错误行，失败不留缓存所以下次触发仍会重试）。

## HTTP 面（回环）

配置存在当前 profile 的 plugin entry 上（`settings.update('loglens', …)` 的 volatile 路径）。

| 动作 | 请求 | 说明 |
|---|---|---|
| 读配置 | `GET /api/dsh-loglens/config` | 返回 `{ ok, config: { enabled, targets } }` |
| 开关 | `POST {"action":"enabled","enabled":false}` | **免同源证明**（禁用后设置卡片是唯一的恢复入口） |
| 新增来源 | `POST {"action":"targets.add","target":{"kind":"loki","label":"本地 Loki","url":"http://127.0.0.1:3100"}}` | `kind` 取 `loki` / `elasticsearch` / `opensearch` / `docker` |
| 改来源 | `POST {"action":"targets.update","id":"<id>","patch":{"url":"…"}}` | id 不可改（它是浏览器侧唯一的引用方式） |
| 删来源 | `POST {"action":"targets.remove","id":"<id>"}` | |
| 查一次 | `POST /api/dsh-loglens/query` `{"target":"<id>","q":"…","from":…,"to":…,"limit":…}` | 面板用；返回行 + 计数 + 截断信号，**形状与 `loglens_search` 一致**（同一个执行层）。可带 `filters`（`{"字段":"值"}`）——面板点榜上下钻时就是这么带的，`/facets` 也会带上同一份 |
| 列字段 | `POST /api/dsh-loglens/fields` `{"target":"<id>"}`（可带 `"limit":80` 收窄） | 分组字段那一格点开时自动拉（面板**不传 `limit`** → 宿主不截断、全列）；真被 `limit` 截了才返回 `truncated: true` 与那句警告，界面照抄 |
| 聚合 | `POST /api/dsh-loglens/facets` `{"target":"<id>","by":"container.name","interval":"5m"}` | 按字段分组 / 按时间分桶（目前只有 ES / OpenSearch 有；面板用 `interval` 画时间分布、用 `by` 画分组榜，工具面是 `loglens_facets`） |

围栏（[docs/design.md §4](./docs/design.md)）：整条路由走**加固档** `isLoopbackRequestStrict`；
`/config` 按**动作**豁免——只有 `enabled` 免同源证明，targets 的增 / 删 / 改要 `hasSameOriginProof`
（跨站页面能从配置侧加一个指向内网的来源，再用读面打它）。**`/query` / `/fields` / `/facets` 也都要同源证明**：
它们只读，却会**替请求方打到已配置的内网目标**并把结果带回来。插件禁用时四条路由里只留 `/config`。
地址只收 http / https 的绝对地址；回环 / 私网 / 公网都是允许面，**链路本地 / 云元数据地址拒**。

```bash
# 读
curl -s http://127.0.0.1:3080/api/dsh-loglens/config
# 加一个本地 Loki：命令行没有浏览器的同源证明，自己带 Origin 头
curl -s -X POST http://127.0.0.1:3080/api/dsh-loglens/config -H 'content-type: application/json' -H 'origin: http://127.0.0.1:3080' -d '{"action":"targets.add","target":{"kind":"loki","label":"本地 Loki","url":"http://127.0.0.1:3100"}}'
```

## 来源地址怎么写

| 类型 | 地址 | 说明 |
|---|---|---|
| `loki` | `http://127.0.0.1:3100` | 可以带网关前缀（如 `https://gw.example/loki`）；查询走 `/loki/api/v1/query_range` |
| `elasticsearch` / `opensearch` | `http://user:pass@127.0.0.1:9200/logs-*` | **索引表达式**：优先用那一行第 3 格下面填的「索引」；没填就用地址路径（兼容旧配置）；两者都没有则是 `*,-.*`（全部索引**但排除 `.kibana_1` / `.infini_*` 这类点号系统索引）。`loglens_sources` 会**回显解析结果**，probe 还会报「最近 15 分钟 N 条」；凭据换成 Basic 头、不进 URL；分页走 PIT + `search_after`；**ES 7.10 / 7.11 也已适配**（PIT 键名与 `_shard_doc` 的差异见 [ROADMAP](./ROADMAP.md)） |
| 公网地址 | 同上，直接填 | **连接面 = 你配置的来源**：回环 / 私网 / 公网一律放行（托管日志服务、内网用公网段都算正常用法）；被无条件拒绝的只有链路本地 / 云元数据那一档 |
| `docker` | 第三格填 **Docker 面板里的目标名**（如 `local`），**不是** URL | 采集来源（设计里的「选项 0」）：agent 侧用现成的 `docker_logs` / `docker_logs_grep`；面板侧走 Docker 插件自己的 `/api/dsh-docker/logs`（相对路径），弱面：无 `until`、`tail` 有上限、无 grep |

## 已知限制

- **Loki 侧的真机验收已完成**（2026-10-12，真 Loki 3.7.8）：分页能力已翻成 `cursor`，同 ts 多行的
  翻页在真机上 **12/12 组不丢不重**（多种 limit × forward/backward）。过程中抓到并修掉两个缺陷
  （`loglens D02`：Loki 的 `end` 是开区间；`loglens D03`：「同 ts 第几行」不是稳定坐标）——
  根因与修法见 [DEFECTS.md](./DEFECTS.md)，真机证据见 [ROADMAP.md](./ROADMAP.md) 的 P2 一节。
  ES / OpenSearch 侧已在真集群上跑过若干轮只读复核，逐条结论同样在 ROADMAP 里，**不在这里复述**。
- **翻页的取舍（明写）**：同一纳秒的行是**切不开的一组**——末组会让这一页**略超 `limit`**
  （宁可多给几行，也不给一个会丢行的游标）；末组大到补不齐时**不给游标**，只报「命中可能不完整」。
- **`tail`（跟随）还没做**：Loki 的 `capabilities().follow` 因此声明为 **`false`**（`stream()` 未实现）。
  这一位会经 `loglens_sources` 原样回给 agent，声明成 true 等于指一个不存在的入口——判据与
  `aggregations` ↔ `facets()` 是同一条。守卫：[test/capabilities.test.ts](./test/capabilities.test.ts)。
  **维护者 2026-10-12 决定「暂缓」**（不是被卡住）：没有消费者，且手上真在用的来源是 ES
  （跟随要走 `_search` + 轮询）——理由与「要做时怎么做」见 [ROADMAP.md](./ROADMAP.md)。
- **两种聚合（时间分布 / 按字段分组）**都画在结果列表**上方**（先看趋势、再看行，与 Kibana 同一顺序；
  2026-10-17 第十五刀从「下方」挪上来的——下方时它排在 100 行日志之后，等于要滚过去才看得见），
  且**只对有聚合能力的来源画**（当前是
  ES / OpenSearch）——能力由宿主随 `/query` 响应下发，面板**不自己按类型猜**（那会是第二份会漂的判据）。
  两份图都**来自后端的聚合**，不是数这一页：那一页被 `limit` 截断过，数它只会得到一个假的分布 /
  假的排名。
  - **时间分布**：按窗口挑分桶档位；相邻桶之间的空档**补 0**——否则「那段时间一条都没有」看起来会像
    「一直在刷」。合计只在没被上限截断时才写。**点一根有数据的柱子 = 放大到那一档**
    （与「点榜上一行」同一条套路：改草稿 → 立刻重查，不拿本地行数糊一个结果）。
    放大出来的窗口住在**草稿**里（`preset: 'custom'` + `window`），经 `runQuery` 的 override 参数进这一枪
    ——不另存一份组件状态，否则点柱子第一枪读到的还是上一轮的窗口（`loglens D04` 那一类
    「说的和查的不是一件事」）。
  - **按字段分组（terms 榜）**：分组字段由用户给（面板**没有默认字段**——各家索引的字段名不一样，猜一个
    等于替用户伪造范围），点开那一格就是当前来源的字段名候选。**不写合计**：列出来的桶加起来不是命中总数，
    没列出来的由宿主的警告原话回报（「还有 N 条落在没列出来的桶里」）；桶计数是近似值时同样照抄那条警告。
    空值键（文档缺这个字段）显示成「（空值）」，而不是一条没有名字的横条。
  - **点桶下钻（结构化筛选）**：筛选按「字段 = 值」下发（宿主契约里的 `filters`），**一个字段只有一条**
    （走的是同一份 `Record`，两条并存会静默盖掉一条）；值**不做 trim**（键名里的空格是内容的一部分，
    裁掉就静默筛不到东西）。**空值那一桶不给点**：筛选表达不了「字段缺失」，给个点得动的入口只会筛出
    别的东西。**Loki 不支持结构化筛选**（宿主会原话报错）——用它时把条件写进 LogQL 查询串；
    界面上那一行也写着这句，因为「换了来源、筛选还留着」是可能的。
  - Loki 没有指标查询，所以它这里两种图都没有，界面上如实写着这一句。宿主**没给**能力自述时（旧版宿主）
    则**什么都不说**——「不知道」不等于「不支持」。
- 面板里的查询区是**受控重复**——设计 §5 三选一的**最终口径**（2026-10-12 拍板，选项 1）：
  日志视图建在本插件自己的卡片里，不与别的插件共享浏览器模块。理由（两份视图不是同一件事、
  选项 2 不是做不到而是不值得）见 [docs/design.md §5](./docs/design.md)。
- Docker 目标在面板里走的是**选项 0 的面板半格**（已接）：相对路径 fetch Docker 插件自己的
  `/api/dsh-docker/containers` 与 `/logs`，弱面（无 `until`、`tail` 有上限、无 grep）在界面上如实标注；
  agent 侧仍只做指路，不包一层。
- 一次只查一个来源（v1 不做跨后端 fan-out）。
- **出站围栏：连接面 = 你配置的来源**（设计 §4.1 / [src/net.ts](./src/net.ts)）：回环 / 私网 / 公网一律放行
  （托管日志服务、内网用非 RFC 1918 网段都算正常用法）；**链路本地与云元数据地址**（`169.254.169.254` 这类）
  **一律拒且无豁免**。**不跟随重定向**：来源回 3xx 时报错并回显 `Location`，改地址重来
  （一次 302 就能把请求带出白名单）。
- 一次请求的体积上限 8 MiB、超时默认 20s；时间窗与条数的上限由宿主夹取并在面板上如实提示。
- 围栏判的是**域名解析之后的 IP**，而解析与建连是两步：两步之间 DNS 翻脸（rebinding）仍有窗口。
  来源地址是操作者自己填的，这一层挡的是事故与过期的名字，不是持域名的对手。
- Docker 只作为**采集来源**（设计里的「选项 0」），不做适配器：agent 侧用现成的 `docker_logs` /
  `docker_logs_grep`，本插件不包一层。
