## 2. 编号字典（这段代码为什么长这样）

### `D01` 块注释里的 `*/` 是注释结束符，不是 glob

**症状**：`packages/loglens/test/loglens.test.ts` 一加载就失败，报 `ReferenceError: test is not defined`，
错误位置指向注释行本身（`packages/*/test/**` 里那个 `*/` 之后）。

**根因**：文件头是 `/** … */` 块注释，而注释里写了一句「vitest 的 include 是 `packages/*/test/**`」——
其中的 `*/` 提前把块注释闭合了，紧随其后的「；由仓库根 `pnpm test` 收集…」于是变成了真代码。

**为什么值得记**：这不是手滑一次就绝迹的错——`templates/hello/test/hello.test.ts` 的同一句里
**专门放了一个零宽空格**来躲开它，而 `pnpm create-plugin` 会把这个文件复制进**每一个**新包
（2026-10-11 建包当天实测：loglens 就是这么整份套件加载失败的）。
写这类「glob 形态」的注释时一律写成 `packages/<pkg>/test/`，不要出现 `*/`。

**修法**：把注释里的 glob 换掉（`packages/<pkg>/test/`），并在这里留下编号。

### `D02` Loki 的 `end` 是**开区间**，不是闭区间

**症状**：真机上「翻下一页」拿不到东西——第二页回 0 行，而且**不只是重复/漏几条，是整批消失**
（P2 真机验收：写入 80 行，翻完只取回 7 行）。

**根因**：`src/cursor.ts` 的设计写的是「窗口右端收到游标那个 ts，**含**边界」，`loki.ts` 就照它
`end = cursor.endNs`。但真 Loki 的 `query_range` **`start` 闭、`end` 开**。真机上逐纳秒扫过：
`start = ts` 命中、`end = ts` 命中 **0 行**、`end = ts + 1ns` 才命中。
于是那一批同 ts 的行整批落在窗口外，第二页什么都拿不到。

**为什么值得记**：这条**在假 Loki 上永远测不出来**——当时的假服务器只是回一份固定 body，
根本不看 `start` / `end` / `limit`。假服务器不实现真语义，反例就是装饰。
（配套修法见 test/loki.test.ts 的 `startRealisticLoki`：现在按真语义过滤 + 截断。）

**修法**：续页边界一律写成 `boundaryNs + 1ns`；`start` 闭区间的性质也一并写进注释与用例。
**注意这条后来被 D03 的修法取代了方向**（现在 forward 是把 `start` 推到边界之后，而不是收 `end`），
但「end 是开区间」这个事实仍是所有窗口计算的判据。

### `D03` 「同 ts 第几行」不是稳定坐标——按**完整 ts 组**翻页

**症状**：修好 D02 之后翻页不再回 0 行，但**原地重复**：真机上连翻 41 页拿到 280 行，
去重后只有 7 行——第一页被反复交付。

**根因**：P1 的游标设计假定「同一 stream、同一 ts 内多行的返回顺序稳定」，用
`streamIdx + ordinalAtTs` 当坐标去跳过已返回的行。真机证伪了两件事：
1. **流在响应里的次序会随查询窗口变**（`start` 不同，同一个 shard 可能排前也可能排后）；
2. **`limit` 切在同纳秒组中间时，Loki 交回的那几行也不稳定**。
位置既然会变，「第几行」就不是坐标，跳过逻辑必然错位。

**为什么值得记**：这是一条**设计前提**被真机推翻的例子——实现、用例、注释三处都自洽，
只是那个前提本身没验过。真机验收的价值就在这里：它验的不是「代码有没有 bug」，是
「**前提成不成立**」。

**修法**：换坐标，不用组内位置，用 **ts 本身**：
- 组内次序改成按**内容**定（标签 + 正文），`LogLine.id` 也改成 `ts:内容序`（不再含流序号）；
- 每页若取满 limit，说明**末组可能被切开** → 单独把那一组整组补齐再交付（组是切不开的）；
- 下一页 forward 从 `末组 ts + 1ns` 起、backward 到 `末组 ts` 止——两个方向都天然跨过整组。

**真机验证**：同一份 120 行（3 流 × 8 个时间点 × 每点同纳秒 5 行），
`limit` 取 1 / 3 / 7 / 11 / 13 / 25 × forward / backward 共 **12 组全部不丢不重**。
见 [ROADMAP.md](./ROADMAP.md) 的「P2 真机验收」一节。

### `D04` 「来源」下拉显示的那一项，必须与真正用的那一项是同一个判断

**症状**：刚进卡片（几个来源、还没选）时，下拉写着第一项（`Docker`），而面板其余部分按「没选来源」走。

**为什么代码写成这样**（现场 / 根因 / 修法与反向验证写在修复提交的 message 与
[ROADMAP.md](./ROADMAP.md) 里，这里只留代码形状）：`<select value="">` 在没有对应选项时会被浏览器
**回落显示第一项**——那是一个源码里看不见的谎。所以 (1) 加一个 value 为空串的占位项，把「还没选」这句话
显式画出来；(2) 下拉的 value 与查询用的来源都取**回落之后的那一项**（`chosenTarget`），
于是「选中的来源被删掉」时两边一起回落，不会出现「下拉写着没选、请求却打一个已经不存在的 id」。
