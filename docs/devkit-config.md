# 统一开发测试套件配置设计

> **待实施的跨包配置设计**。当前已有项目上下文模型 MVP，并在 devdata 配置卡片接入只读“快速开始（预检）”；仅校验上下文字段，统一配置、三面投影、清单检查与执行编排尚未接线。
> 本文负责快速开始与跨包编排；数据通路及包边界仍以 [devdata-plan.md](./devdata-plan.md) 为准，
> 包内用法与实施进展见 [devdata](../packages/devdata/README.md)、[devenv](../packages/devenv/README.md)、
> [devfront](../packages/devfront/README.md) 及各自 ROADMAP。

## 目标用户流程：项目 → 模式 → 环境 / 数据 / 页面 → 预检

让使用者先回答“在哪个项目、要核验什么”，再填写各面独有的连接信息。入口放在现有三面快速开始流程中，
第一阶段沿用 devdata 的配置入口；统一的是编排视图，三个包仍可独立安装、配置和调用。

1. **项目**：显式选择本机项目根与项目名；展示实际路径，禁止猜宿主 cwd。项目名用于三面清单对齐，
   不要求等于目录名。路径不存在或不是目录时在预检中定位到 `root`。
2. **模式**：默认 `readonly`（日常只读观测），可选 `release`（发布后只读核验）。后者组织
   “环境就绪 → 数据断言 → 页面断言”的顺序；不调用 Jenkins、不部署、不启停容器，也不授予写能力。
3. **环境 / 数据 / 页面**：默认全部关闭，用户显式启用所需面。优先引用各包已经声明的目标，显示来源与
   实际 scope；新建目标时进入对应包的受管编辑路径。连接簿、引擎、库、URL、凭据引用仍在各面填写。
4. **预检**：先只做配置与清单检查，展示逐字段问题、投影差异和恢复入口；用户另行触发有界的只读连接
   检查。通过预检后才可保存草稿或开始核验，保存配置与执行核验是两个明确动作。

未启用面显示 `disabled`，不读该面清单、不注册额外能力、不派发请求。已启用但未装包、缺目标、缺清单
或无执行器时明确标为不可运行；不自动开启插件、不创建默认目标、不扫描目录发现项目。

## 统一项目上下文：沿用现有 API

模型与实现真源是 [project-context.ts](../packages/devdata/src/project-context.ts) 的
`normalizeProjectContext(input: unknown): ProjectContextResult`，入口由 devdata 导出；调用示例见
[devdata 快速开始](../packages/devdata/README.md#快速开始-mvp--当前边界)。编排层先调用它，失败即停止投影。

| 字段 / 结果 | 契约与编排用途 |
|---|---|
| `root` | 必填本机绝对路径；去两端空白并词法归一化。相对路径、`~`、NUL 不接受；调用各面时显式传为 `cwd` |
| `project` | 必填；去两端空白，以字母或数字开头，只含字母、数字、点、下划线、短横线；每个调用显式传入，不依赖目录名缺省值 |
| `mode` | `ProjectMode = 'readonly' \| 'release'`，缺省 `readonly`；只决定流程 |
| `enabled` | `ProjectFace = 'environment' \| 'data' \| 'front'` 的布尔映射，缺省各为 `false`；成功输出是独立、已冻结的开关对象 |
| `readOnly` | 成功输出固定为 `true`；不是输入字段，也不是目标权限快照 |
| 成功 | `{ ok: true, context, problems: [] }` |
| 失败 | `{ ok: false, context: null, problems: [{ field, message }] }`；未知顶层字段、未知面、非法模式或非布尔开关均逐字段报问题 |

该纯函数不修改输入、不取 cwd、不读文件、不解析符号链接、不证明目录存在、不连接目标、不保存配置。
文件系统检查与目标解析属于后续预检；其结果不得被当作 scope 授权。不能把 `target`、连接参数、能力声明
或 `readOnly` 塞进该 API 输入，未知字段会被拒绝。

三面目标引用放在**独立的编排绑定草稿**中，以下是设计形状，尚无保存 API：

```ts
const contextInput = {
  root: '/work/demo', project: 'demo', mode: 'release',
  enabled: { environment: true, data: true, front: true },
}
const bindings = {
  environment: { target: 'test-host' },
  data: { targets: ['test-redis'] },
  front: { target: 'test-site' },
}
```

草稿只存上下文输入和目标引用，不复制连接、口令、scope 或授权事实。数据面允许多个目标：预检逐条核对
断言声明的目标是否在显式选择集内；选择集外的条目标为未执行，不能静默跳过后报整面通过，也不改写断言的
`target`。发布清单里的 `target` 仍按现有页面面语义解析，不把它升级成三面通用目标。

## 三包映射：编排入口，不合并万能 target

| 面 | 配置继续归谁管 | 项目清单 / 只读执行入口 | 编排层投影 |
|---|---|---|---|
| 环境 `environment` | devenv 的 `local/ssh` 目标、连接簿引用、scope、探针和等待预算 | `ready/<project>.ready.yaml`；`env_status` / `env_wait` | `root → cwd`，`project` 原样传入，绑定环境目标 id |
| 数据 `data` | devdata 的引擎、环境四态、连接、库、scope、凭据引用及护栏 | `verify/<project>.yaml`；`devdata_verify` | 相同 `cwd/project`，按每条断言自己的目标派发，不替换成环境目标 |
| 页面 `front` | devfront 的站点 URL、允许源、scope、视口、凭据引用及登录声明 | `web/<project>.yaml`；`site_verify` | 相同 `cwd/project`，绑定站点 id；继续使用同源与路径前缀判据 |

编排层只整理参数、差异与报告，调用各包原有受管入口，不直连执行器、不另写裁决器或清单解析器。
共享的只有项目上下文与显式的绑定关系；连接簿条目不等于数据库目标，数据库目标不等于站点。
同名 id 也不能作为跨包自动映射依据。

预检分两步：**静态**检查上下文、目录、包可用性、引用存在性、scope、清单形状与项目名对齐，并列出
当前工具 / 执行器是否可用；**可选只读探测**再走对应包入口取事实。静态报告不声称连通或就绪，连接成功
也不等于断言通过。现有证据链总览只能提供清单形状；各面解析与执行仍由本包负责。

`release` 的后续编排先等环境就绪，再运行启用的数据与页面核验；环境未就绪、被否证或取消时，依赖步骤
标为未执行并保留原因，不报成功。用户仍可单独进入各包复核。报告保留原包状态、证据、时间与拒绝码，
统一视图只增加“配置有效 / 可运行 / 已执行”的区分，不把三套求值状态强行改成同一种布尔值。

## 安全不变量

- **只读是执行约束**：两种模式均只派发只读核验入口；即使目标已有写授权，也不调用 `env_up/down`、
  数据写命令或页面 `click/fill/login`。需登录的页面由用户单独走已有受管登录流程；本入口不自动登录。
  `readOnly: true` 只是上下文声明，实际约束还必须由入口白名单与各包判据保证。
- **scope / audit / 能力闸门不绕过**：每次调用显式带项目根，由各包重新裁决；空 scope 保持处处拒绝，
  不把 root 自动补进 scope，不因“测试”或 `release` 改环境标签。审计包含拒绝，审计失败继续 fail-closed；
  统一报告不能代替原审计。能力来源、声明及 TOFU 指纹不经统一表单改写或授权。
- **配置编辑同样受管**：目标与站点保存沿用逐次确认、严格校验、审计和官方 settings 通道；能力只读字段
  仍拒绝写入。保留现有能力、登录等未编辑字段；项目站点声明只在既有宿主开关允许时读取，不能自动打开。
  凭据只存引用，解析结果不进草稿、预检报告、日志或审计；浏览器沙箱默认保持开启。
- **unknown 不折叠**：目标环境的 `unknown` 继续禁止写；核验结果的 `unknown` 表示没验成。
  缺证、截断、不可达、无执行器、取消及未执行均不得变成通过；配置错误另列字段问题。
  环境面的 `ready/unready/refuted` 保留原语义。汇总出现未执行或 unknown 时，不能给“全部通过”。
- **预检不是授权缓存**：配置或上下文变更后旧预检失效；实际执行重新校验当前目标、scope 和能力。
  对外请求、输出截断、取消及预算继续遵守各包契约和 [跨包行为约定](./architecture.md#7-一条请求经过什么)。

## 迁移与分阶段实施

既有三包配置与工具参数继续有效；不重命名目标、不移动清单、不新增万能 target、不批量重写 profile。
从现有配置导入时只生成草稿候选，用户明确选择项目与绑定；冲突、缺失和多个候选都展示出来，不默认取第一项。

| 阶段 | 实施内容 | 出阶段门槛 |
|---|---|---|
| 模型 MVP（已有） | 沿用项目上下文纯函数；暂不把模型存在写成 UI 已落地 | 现有 API 用例覆盖缺省值、逐字段错误、输入不变与冻结开关 |
| 投影与预检 | 独立纯投影模块、各面适配器、差异预览；先支持引用既有目标，不写配置、不联网 | 同一上下文生成正确 `cwd/project`；scope 外、缺目标 / 清单 / 执行器给出明确原因；拒绝路径执行器零调用 |
| 快速开始与保存 | 接入表单和字段错误定位；草稿持久化设计单独评审，连接配置仍调用各包保存通道 | DOM 实填保存后 HTTP 读回；未编辑字段保留，能力字段写入被拒；`persisted: false` 明示未落盘 |
| 只读执行编排 | 显式探测与 release 顺序执行、取消 / 预算转发、分面报告与恢复入口 | 真实三面核验有证据；unknown、依赖未执行和取消不报通过；原审计仍完整 |

保存按包分别确认与提交，不宣称跨包事务。部分保存成功时列出已落盘、仅本进程生效、失败及待保存的面，
重试只针对失败项；关闭统一入口即回退到原卡片与工具，不需要还原或删除原配置。跨包待办与落点分别回填
各包 ROADMAP，本文保持配置设计的唯一归宿。

## 验收标准

- 从空草稿走完“项目 → 模式 → 三面 → 预检”：缺省 readonly、三面关闭；未启用面无清单读取或执行。
  非法字段定位准确，任何模型错误都没有可执行上下文。
- 使用目录名与项目名不同的 fixture，三面仍读同一个显式项目；不存在目录不伪装成缺清单，项目名串线报配置
  问题。数据多目标逐条对齐，站点 / 数据 / 环境的同名 id 不发生自动互换。
- 越界、空 scope、能力字段注入及审计失败的反例保持原拒绝码；执行器未被调用。
  切到 release 或保存目标不会授权写、扩 scope、抹能力 / 登录字段或泄露凭据。
- 分别验证缺清单、无执行器、不可达、截断、页面观察失败、环境未就绪与取消：报告保留原语义和恢复路径，
  未执行不计通过；静态预检通过不能显示“环境已就绪 / 数据正确 / 页面正确”。
- UI 阶段必须有真实 DOM 保存 + HTTP 复核，执行阶段按 [真机约束](./agent-real-test.md) 使用隔离
  `DSH_HOME` 和可识别临时资源，自证真实配置未变；SKIP 单独列出，不能作为验收通过。
- 实施代码时运行相关包 typecheck / 单测和全仓门禁，新增编排不变量随阶段配反例守卫。
  本文的文档门禁为 `node scripts/docs-index.mjs`、文档链接检查及 docs-index 用例；
  登记以 [知识归属表](./conventions.md#知识归属表唯一归宿) 为准。
