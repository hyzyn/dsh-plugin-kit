## 一句话

语言**只认宿主**（`@deepseek-ai/dsh-client-locale` 的 `ctx.locale`）；每个包自带
`zh` + `en` 两份目录，用**同一段照抄的安装代码**注册进去；目录与用法由
`scripts/check-i18n.mjs` 静态校验。**不建共享模块、不引入构建步骤、不自己读
`navigator.language`。**

## 为什么不建共享模块（三条硬约束，都实测过）

1. **插件之间不许互相 `import`**（[architecture.md § 3](./architecture.md#3-依赖方向不许反向)），
   而 `@hyzyn/dsh-kit` 是**宿主半体**库：它的入口 import 了 `node:dns` / `node:fs` /
   `js-yaml`，没有可用的浏览器子路径。想在浏览器侧共享一段代码，唯一被允许的通道是
   **宿主提供的服务**——那正好就是 `ctx.locale`。
2. **10 个包里只有 3 个有构建步骤**（`tty` / `docker` / `codegraph` 走 esbuild 或文本内联），
   其余 7 个的 `client.js` **就是源文件**。为 i18n 给这 7 个包引构建，是把一件小事变成
   一次有回归风险的搬家。
3. **宿主已经把语言策略做完了**：持久化偏好（回环页面写 `$DSH_HOME`）、浏览器推导、
   原生壳的 `__DSH_LOCALE__`、以及「设置 → 通用设置 → 语言」那一行。插件再自己推导一遍
   `navigator.language`，就是 ROADMAP 原文警告的「两套互不兼容的写法」。

## 规范片段（**照抄**，不要自己发明写法）

闸门会检查这五点都在（`checkInstaller()`）：`installI18n(ctx)` 被调用、
`ctx.inject(['locale']`、`register(I18N_NS, 'zh'`、`register(I18N_NS, 'en'`、`i18nFallback`。

```js
/* ==== dsh-i18n:begin ==== */
const I18N_NS = 'demo'            // = 插件 id（conventions § 命名）
const I18N_ZH = {
  'card.name': '演示面板',
  'msg.saved': '已保存 {count} 条',
}
const I18N_EN = {
  'card.name': 'Demo panel',
  'msg.saved': 'Saved {count} entries',
}
/* ==== dsh-i18n:end ==== */

/** 占位符替换：`{name}` → params.name（缺参留空，不抛错——文案不该打死界面）。 */
function i18nFormat(text, params) {
  if (params === undefined) return text
  return String(text).replace(/\{(\w+)\}/g, (_match, name) => (params[name] === undefined ? '' : String(params[name])))
}

/** 中文兜底：老宿主（DSH ≤0.1.5）没有 locale 服务时，界面不能变成一串键名。 */
function i18nFallback(key, params) {
  return i18nFormat(I18N_ZH[key] !== undefined ? I18N_ZH[key] : key, params)
}

let t = i18nFallback

/**
 * 注册目录并绑定翻译函数。**动态 inject**：老宿主上回调永不触发、`t` 保持中文兜底；
 * 写成静态 `inject: ['locale']` 会让整张卡片在老宿主上根本不挂。
 *
 * 语言切换不用自己订阅：插槽 outlet 随 locale revision 重渲染（renderer 的
 * `useLocaleRevision`），而 `bind()` 返回的翻译函数在**调用时**读当前语言。
 */
function installI18n(ctx) {
  ctx.inject(['locale'], (i18nCtx) => {
    const disposeZh = i18nCtx.locale.register(I18N_NS, 'zh', I18N_ZH)
    const disposeEn = i18nCtx.locale.register(I18N_NS, 'en', I18N_EN)
    t = i18nCtx.locale.bind(I18N_NS)
    return () => {
      disposeEn()
      disposeZh()
      t = i18nFallback
    }
  })
}
```

`apply` 第一件事就是 `installI18n(ctx)`，之后所有界面文案走 `t('key')` /
`t('key', { count })`；**不再出现中文字面量**（`Kit` 这类品牌词、`KEY` / `value` 这类
输入示例、`js:process.env.XXX` 这类语法示例不算文案，原样保留）。

## 目录放哪

**一律内联在该包的「主客户端半体」里**（`client-src/index.js`，或手写包的 `client.js`），
用上面那对标记框住：

| 包的形态 | 主半体 | 为什么内联而不是单独一个文件 |
|---|---|---|
| 有构建步骤（`tty` · `docker` · `codegraph`） | `client-src/index.js` | `codegraph` 的 `scripts/build-client.mjs` 是文本变换脚本，遇到**任何残留 import 直接 `exit(1)`**；为 i18n 去改构建脚本得不偿失，而 `tty` / `docker` 用同一形状省掉「两种写法」 |
| 手写 `client.js`（其余 7 个） | `client.js` | 没有构建步骤，`client.js` 就是源；而且**一旦凭空建出 `client-src/`，仓库级「宿主地址来源」静态规则会停止覆盖 `client.js`**（`scripts/client-host-url.mjs` 的 `listClientSourceFiles()` 在目录存在时只扫 `client-src/**`） |

闸门**会扫该包的全部客户端半体源**（`client-src/*.js`，或只有 `client.js`）：目录块只认一处，
但 **`t('…')` 用法的对账与「还剩多少中文」的度量都跑在全部源上**——`tty` / `docker` 的界面
文案散在 `stats-bar.js` / `log-buffer.js` 这类兄弟模块里，只看主半体会漏。

## 键名规范

`域.名`，用 `.` 分层。**域只有一个词、必须在本表里**（闸门按白名单查：域不在表里就报错，
「先在本表加一行，别各自发明」）；**名可以是 camelCase**（`list.minutesAgo` / `btn.addServer`），
同一包内保持一致即可。

| 域 | 放什么 | 例 |
|---|---|---|
| `card.` | 卡片 / 页面的名字与简介（含 `settings.*.item` 的 `label`） | `card.name` · `card.desc` |
| `panel.` | 面板内的标题、小节名 | `panel.title` · `panel.createTitle` |
| `list.` | 空态 / 加载态 / 列表项上的文案 | `list.empty` · `list.loading` · `list.minutesAgo` |
| `btn.` | 按钮文字 | `btn.save` · `btn.copyCommand` |
| `field.` | 表单字段的标签与占位符以外的说明 | `field.name` · `field.transport` |
| `option.` | 下拉 / 单选项的文案 | `option.baseTemplate` |
| `check.` | 复选项的文字 | `check.secret` |
| `editor.` | 编辑页的标题等 | `editor.createTitle` · `editor.editTitle` |
| `section.` | 设置大类页面（`settings.section`）自己的文字 | `section.title` · `section.intro` |
| `badge.` | 列表项上的徽标 | `badge.active` · `badge.versionCount` |
| `status.` | 连接 / 运行状态 | `status.active` · `status.notLoaded` |
| `hint.` | 表单内的一段说明 | `hint.editor` · `hint.chars` |
| `banner.` | 列表顶部的横幅（信息 / 告警 / 错误） | `banner.conflicts` · `banner.fileError` |
| `meta.` | 结果里的元信息前缀 | `meta.duration` · `meta.tools` |
| `msg.` | 操作结果（成功 / 进行中） | `msg.saved` · `msg.creating` |
| `error.` | 失败与校验错误 | `error.nameRequired` · `error.saveFailed` |
| `prompt.` | 用 `window.prompt` / 输入框向用户要一个值 | `prompt.rename` · `prompt.port` |
| `confirm.` | 用 `window.confirm` 提出的确认 | `confirm.delete` · `confirm.removeLast` |
| `placeholder.` | 输入框占位符（**语法示例不翻**） | `placeholder.name` · `placeholder.sidebar` |
| `version.` / `ab.` | 包内特有的分组（版本管理 / A-B 测试） | `version.initialNote` · `ab.banner` |

**两条写法要求**：

1. **值在句子里就用占位符**，不要拼接：`'已创建 profile：' + name` → `t('msg.created', { name })`。
   判断标准是**值会不会影响语序**——`serverName「X」已被占用` 在英文里是
   `serverName “X” is already taken`，值在中间，必须用参数；而
   `'保存失败：' + error.message` 这类「前缀 + 值」两种语言都成立，留着拼接可以（少一层嵌套）。
2. **句子里出现的标点跟着语言走**：中文顿号 `、`、全角空格 `　`、全角括号 `（）`、直角引号 `「」`
   都不能写死进英文界面——要么进目录（占位符），要么改成 ASCII（`', '` / `' · '` / `()`）。
   闸门的中文度量把**全角标点也算中文**，就是为了不漏这一类（`web（base + web-app）` 里
   一个汉字都没有，早期版本报「0 条」）。

## 闸门查什么、不查什么

`node scripts/check-i18n.mjs`（CI 的 ubuntu step + `.githooks/pre-commit`，
纯逻辑用例在 `scripts/test/i18n.test.ts`，判据自检 `--self-test`）：

**查**（任一不过即红）：命名空间 = 包名；zh/en **键集一致**；**占位符一致**；
空值 / 非字符串；**重复键**（JS 后写覆盖前写，求值后看不出来）；代码里
`t('…')` 用到的键**必须有定义**；安装片段五点在位。

**只度量、不判定**：成功行上会打「剩余中文字面量 N 条」——品牌词（`Kit`）、语法示例
（`js:process.env.XXX`）、宿主返回的错误正文都不该被翻，所以这个数字由人复核
（闸门读不懂语义，「这条该不该翻」是人的判断）。**迁移完成的判据**：该包剩下的每一条中文
字面量都能说出「为什么它不该被翻」。

**不查**（写在这里免得被当成遗漏）：译文质量（闸门读不懂语义）；运行期行为
（老宿主上 `t` 是否真退回中文——那靠每包单测与真机）；动态键（`` t(`row.${i}`) ``
或 `t('row.' + i)` 只能**告警**，不能静默忽略）；宿主半体与 agent 面向的文案（见下）。

## 范围纪律

- **只翻浏览器半体的界面文案。** 宿主半体（`src/**`）与 agent 面向的文案**不在范围内**：
  - 工具 `description:`、`*_GUIDANCE`、`systemPrompt.section` 是**模型读的提示词**，
    翻它等于改提示词，会连带影响契约测试与采纳率观测；
  - 工具**输出**里的中文（如 `tty_list` 的渲染文案）是 agent 的输入，同理；
  - 宿主半体的报错正文（HTTP 响应里的 `error`）保持中文：`ctx.locale` 是**浏览器侧**
    服务，宿主半体看不到它。要翻它得先定一套宿主侧语言来源，那是另一件事。
- **不改 zh 与 en README 的关系**：本方案只覆盖 GUI；文档语言策略仍见
  [conventions.md § 文档分档](./conventions.md#文档分档)。

（产物随源码入库，`git diff --exit-code -- 'packages/*/client.js' ':(glob)packages/*/lib/**'` 要干净）。

**已搬包的经验**（写给下一个搬的人）：

1. **匹配/定位数据不要翻**（`search` 的 42 条）：双语数组是"按任意语言的 DOM 文本找元素"的实现，
   翻掉等于把另一种语言下的用户挡在门外。
2. **HTML 串里的文案要 `esc(t(…))`**（`mcp` / `prompt`）：原先 `&lt;` 是写死在标记里的，拆出来之后
   转义责任跟着文案走，否则 `mcp__<serverName>__<tool>` 会被 innerHTML 当成标签。
3. **拼接句改成占位符**：`'已创建 profile：' + name` → `t('msg.created', { name })`；英文语序不同，
   别留成 `t('a') + name`。
4. **测试与 smoke 的断言通常不用改**：夹具里没有宿主 locale 服务 → `t` 走中文兜底 → 渲染出来
   仍是中文（这正是「兜底必须在」的另一个理由）。

## 预览与 smoke 夹具（**迁移一个包就要补一次**）

客户端半体迁移后，`exports.apply` 第一句是 `installI18n(ctx)` → `ctx.inject(['locale'], …)`。
**假宿主如果没有 `inject`，整条 preview / smoke 会当场抛 `TypeError: ctx.inject is not a function`**
（`search` 的 `scripts/preview/mock-host.js` 就这么炸过；CI 不跑 preview，所以不会红，只有人会发现）。

所以每搬一个包，顺手检查它的夹具：

| 夹具 | 要补什么 |
|---|---|
| `packages/search/scripts/preview/mock-host.js` | ✅ 已补：假 `inject` + 假 locale（`register` / `bind`），`window.__previewLocale = 'en'` 可预览英文 |
| `packages/tty/scripts/preview/harness.js` | inject 已有（服务表）→ 服务表里加一项 `locale`（同形状的桩） |
| `packages/docker/scripts/client-smoke.mjs` | inject 已有，且**只对白名单里的服务回调**（`ttyConnbar` / `ttyPanel` …）→ 不回调 `locale` 正好就是「老宿主」那条路（渲染中文），既有的 12 条中文值断言 + 52 条中文正则因此**照旧绿**；别把 `locale` 加进必断言列表 |
| `packages/rss/scripts/client-smoke.mjs` | **不用改**：它是**静态**冒烟（读 client.js 文本做断言，不挂载、没有 ctx）；它断言的中文子串在 zh 目录里原样保留 |
| `packages/codegraph/scripts/preview-card.mjs` | ✅ 已补：假 `inject` + 假 locale（`DSH_PREVIEW_LOCALE=en` 可预览英文）；另有两处 `findButtonByText` 改成双语匹配（按钮文案已进目录） |

**夹具里没有 locale 服务时渲染出来是中文**（兜底），所以既有的中文断言不用改——这也是
「zh 目录必须留作兜底」的第二个理由。**反过来**：如果某个夹具**提供**了 locale 服务，
就必须让它能选语言（否则它测的就是一条不存在的路），`search` 那套用
`window.__previewLocale = 'en'` 切换。

## 已知陷阱（都是实测踩过的）

1. **esbuild 会把中文转义成 `\uXXXX`**（没配 `charset`）：`packages/tty/client.js` /
   `docker/client.js` 里**一个裸中文字符都没有**。所以**不要**写「产物里必须含中文」这类闸门
   ——它对这两个包恒绿；要看产物请解转义，或者干脆只信源码侧闸门。
2. **不要用插槽的 `locale:` 选项**（`ctx.slots.register({ locale: NS, … })`）：声明了它
   而宿主没有渲染器的 locale 面就是**装配失败**，而本仓插件仍要支持 DSH ≤0.1.5。
   本方案一律走 `bind()`。
3. **`register(ns, locale, dict)` 对重复的 `(ns, locale)` 直接抛**：所以注册必须能随
   插件卸载而释放——这就是片段里 `return () => { disposeEn(); disposeZh() }` 的作用
   （HMR 重挂时先释放旧的）。
4. **`zh` 目录必须留作兜底**：宿主查不到键时**显示键名本身**（`card.name`），
   所以没有 locale 服务的老宿主上必须由 `i18nFallback` 接住。
5. **闸门必须在直接执行时才跑**（`check-i18n.mjs` 底部的 `invokedDirectly` 判断）：
   它在 `scripts/test/i18n.test.ts` 里被 import，若 import 期就 `process.exit(1)`，
   一个包的目录写错会打死整跑测试的进程。
6. **英文目录不是「顺手翻译」**：键集与占位符由机器比对，但译文质量只能靠人读一遍。
   正式发布前至少把一个包的语言切成 `en` 走一遍真实界面。
